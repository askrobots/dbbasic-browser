dbbasic-browser

A browser that pays for the web itself — with a built-in password manager and a remote-control API.

Getting started

Type a URL and press Enter. Plain hosts default to https://; localhost and private-network addresses default to http://. Anything that isn't an address is a search, answered by askrobots.com. The first tab and every new tab open askrobots.com (HOMEPAGE=https://… changes that). The local x402 demo gallery is under Help ▸ x402 Demo Gallery (start it with node apps/browser/demo/x402-demo-server.mjs); ▶ Tour always walks that gallery.

Toolbar, left to right: back / forward / reload, the address bar, then Keep, Save (to your askrobots bookmarks), x402 tests and Tour (the demo gallery), Bookmarks, Chat, Reader and Passwords. In a narrow window the buttons show only their icons.

The status bar along the bottom: on the left, what the page is doing (or where a link you point at goes); on the right, what the browser is using and spending: Memory (click for what each tab uses), x402 (the payment inspector), your wallet balance, Fund, and Paid this session. A chip appears there when the automation API is on, and a red badge while the caller network is on.

Every feature is also in the menu bar: File (tabs, downloads), View (Reader, Chat, the x402 inspector, what the browser is using), Go (back ⌘[ or ⌘←, forward ⌘] or ⌘→, next and previous tab; the arrows go to a text field when one has the focus), Bookmarks (save ⌘D, show ⌘⇧B, Keep, kept copies), History (show ⌘Y, pause, forget) and Tools (passwords, connections, the wallet, the test gallery and tour).

The address bar

Type an address to open it, or anything else to search askrobots.com. As you type, a list shows what Enter will do first, then open tabs (pick one to switch to it), your askrobots bookmarks, pages from your history (from all your computers), your kept copies, search suggestions, and last, Ask the assistant. ↑ ↓ pick, Enter opens, Esc closes the list (twice puts the page's address back). A site you have saved, kept, visited or have open is completed as you type ("slash" → slashdot.org); type on to replace the completion, or delete it.

Tabs, bookmarks, history and kept copies are matched on this computer. For history the browser keeps a copy of the list (addresses, titles and times, never the pages' text) in a file only you can read; it is brought up to date from your askrobots account, so a page forgotten anywhere goes from the suggestions, and signing out deletes it. Search suggestions come from askrobots.com, and are asked for only when what you typed is not an address (never a path, a port or anything with @), without cookies, and never while the caller network is on; switch them off at the bottom of the list.

Tabs, suggestions and the bookmarks panel show each site's icon. The browser fetches a site's icon once, from the first of its pages you open (without cookies, and again after a week), and keeps it in a file only you can read. Typing never fetches one, so a page from your history that this computer has not opened shows the plain symbol. No icons are fetched while the caller network is on or for a site on your never-record list, and forgetting a site forgets its icon.

/ commands. With askrobots connected, type / to list the askrobots tools your sign-in may use (the server decides which), with the site's short names too (/note, /task, /search, /websearch). Tab completes a name; the rest of the line is the tool's first argument (/note buy milk), and the row shows what will be sent before Enter runs it. Every command and its answer go into the chat, so you can ask about them next (“open the second one”); the assistant is told the answer came from your account, not from you. A save shows a note saying what was saved (“Saved note: buy milk (private)”) with Open for its page on askrobots; a search or list opens the chat, each thing found linked to its askrobots page. Links only ever point at askrobots itself. Once an answer from your account is in the conversation, anything the assistant does that could carry it out of the browser (typing into a page, opening an address) asks first, in any mode; Clear forgets it. A tool the server marks as destructive, or one it says nothing about, asks first: press Enter a second time. A tool that needs more than one argument says so instead of running. Without a sign-in, / only offers to connect and sends nothing; a line starting with / is never sent as a search. ⌘K is left to the page (askrobots' own search box uses it), even when the address bar has the focus.

Tabs

Each tab is its own page with its own payment inspector, so spend is attributed to the page that caused it. A ⚡ on a tab means something was paid for there. Links that open a new window (target="_blank") open as tabs; clicking a transaction in the inspector opens it beside the paid page rather than replacing it. Tabs are not yet restored between launches.

History

While you are signed in to askrobots, the pages you visit are kept in your history on your askrobots.com account, so you can find one later by a few words you remember. Each visit keeps the address, the title, when, how long, and the page's visible text (up to 50 KB). Signed out, nothing is recorded.

  • Never recorded: sign-in and payment pages (by address, by title, or when a password field shows), pages on this machine or your private network, anything you looked at for under two seconds, sites on your never-record list, and anything while history is paused or the caller network is on.
  • Addresses are cleaned first: the part after # and every query parameter are dropped, except the few that say which page it is (a YouTube video's v and list, a Hacker News id). askrobots drops them too.
  • Your controls: the History button in the status bar pauses and resumes. The History menu forgets this page, this site or the last hour, and stops a site from ever being recorded. Show History (⌘Y) opens your history on askrobots.com, where you can search it and forget everything.
  • The assistant can search your history to answer "where did I see…?", but it asks you every time, because what it finds goes to its AI company. It can never record or forget anything.
  • Never sent to the search site. History lives on your account only. Pages waiting to be sent are held in memory; signing out, or in as someone else, throws them away.

It needs the history permission on your askrobots sign-in. If the status bar says History off, connect to askrobots again from the assistant panel. The automation API has history.state, history.flush, history.pause, history.forget and history.never.

AI Reader

Click Reader (or ⌘⇧R) for a clean reading view of the current page with a TL;DR at the top. The article is extracted on your computer with Mozilla's Readability and shown in a plain, script-free page; pages that aren't articles fall back to their visible text. Only the TL;DR comes from an AI provider, so a summary can never rewrite what you read — the original text is right below it.

Privacy

  • Nothing is sent unless you click Reader. The first summary per provider each session asks first, naming the provider, model, site and amount of text.
  • Pages with a visible password field are never read.
  • Every provider call raises a toast saying what was sent, to whom, and the cost when known. API keys never leave the main process and are never shown in the UI.
  • The page's text is treated as untrusted data by the summarizer, and the summary is written into the reader with textContent only.

Setting up keys (never in the repository)

Put ANTHROPIC_API_KEY and/or OPENAI_API_KEY in your environment, in the file named by DBB_ENV_FILE, or in ~/.dbbasic/env (plain NAME=value lines). Only those names are read from a file. View ▸ AI Provider switches provider; Anthropic is the default. DBB_AI_MODEL_ANTHROPIC / DBB_AI_MODEL_OPENAI choose models. The defaults are small and fast — claude-haiku-5-5 and gpt-5.4-mini — because a TL;DR is a one-click job; set DBB_AI_MODEL_ANTHROPIC=claude-opus-5-5 for richer summaries at roughly 40× the cost. See .env.example.

Automation

reader.open {tab?, ai?, acknowledge?, wait?} opens the reader; the page text is sent to a provider only when acknowledge: true is passed. ai.status and ai.provider {provider} read and switch the provider. DBB_AI_CONSENT=1 pre-answers the consent prompt for scripted runs.

Downloads

A download opens the standard macOS Save dialog with the file name the site suggested (made safe: path separators and control characters are replaced, so a hostile name can't reach outside the folder you pick). While it runs, the status line shows ⬇ Downloading name — 1.2 MB of 3.0 MB; when it ends a toast says it was saved (with the x402 amount if the download was paid for) or failed. File ▸ Show Last Download in Finder and Show Downloads Folder take you to the file. Downloads are never opened automatically, and on macOS each file is marked as downloaded from the internet (the quarantine attribute), so Gatekeeper vets anything you later run. downloads.list in the automation API lists them; DBB_DOWNLOAD_DIR=/some/folder skips the dialog and saves there, for scripted runs.

Loading indicators

Each tab shows what it is doing, and the status line at the bottom left says it in words: waiting (request sent, no answer yet), receiving (with the bytes so far), redirecting, a site's bot check, an x402 payment (needed, paying, paid), slow (still waiting after 6 s), failed or offline. These come from real signals — what our own network layer and the payment engine see — so DNS, TCP and TLS, which happen inside Chromium, appear as "waiting" rather than as invented phases.

The animations follow your system's "Reduce motion" accessibility setting (on macOS: System Settings ▸ Accessibility ▸ Display): with it on, each state shows a still frame. View ▸ Loading Animations lets you override that with Always or Never.

x402 payments

When a server answers 402 Payment Required, the browser reads the price before paying, applies your spending policy, and either pays, asks you, or refuses.

  • Auto-approve below the policy threshold (default $0.05); ask above it, with a native dialog showing the price; refuse unknown tokens/networks.
  • Every decision is visible: a toast, a row in the x402 inspector (request, challenge, decision, signed authorization, settlement), and the session spend meter.
  • Real settlement happens on Base Sepolia testnet. Use Fund to get testnet USDC; Refund returns the merchant wallet's balance to you.

Password manager

Click Passwords to create a vault. It is one encrypted file (scrypt key derivation + AES-256-GCM) on this computer, protected by a master password. There is no recovery if you forget it, and nothing is uploaded anywhere.

Saving

Sign in to any site. After you submit, a bar offers Save (or Update if the password changed). The offer survives the redirect after login. Only real keyboard/mouse submissions trigger it — a page can't fake one.

Signing in

On a page with a login form and a saved login for that exact site, a bar offers Sign in as … (fill and submit) or Fill. Nothing is filled until you click. The Passwords panel also lists this site's logins, lets you save one manually, generate a strong password, and delete entries.

How it stays safe

  • Exact origin matching: scheme + host + port must all match. www.example.com never fills example.com; lookalike domains never match.
  • Secrets stay out of the UI: the page hands a submitted login straight to the main process, and fills go main → page. The browser chrome only ever sees usernames and origins.
  • Auto-lock after 10 minutes of inactivity; Lock in the panel locks immediately.

Standalone

The vault is also a stand-alone package with a CLI — packages/vault:

npm start -w @dbbasic/vault -- init
npm start -w @dbbasic/vault -- add https://askrobots.com dan --generate 24
npm start -w @dbbasic/vault -- get askrobots.com          # prints the password only
# set DBB_VAULT=/path/to/vault.json to use a specific file, DBB_VAULT_PASSWORD for scripts
The browser's vault file lives in the app's data folder (override with DBB_VAULT). Point the CLI at the same file to share it.

Automation API

Drive this browser from scripts, tests and agents — the same window you are looking at, with payments and the vault as first-class citizens. It is off by default. Start the browser with:

DBB_CONTROL=1 npm start -w @dbbasic/browser     # listens on 127.0.0.1:9777 (DBB_CONTROL_PORT to change)

The URL and a per-launch bearer token are written (mode 0600) to ~/.dbbasic/control.json. Call POST /rpc with {"method": "…", "params": {…}}; the answer is {"ok": true, "result": …} or {"ok": false, "error": {"code", "message"}}.

TOKEN=$(jq -r .token ~/.dbbasic/control.json)
curl -s -H "Authorization: Bearer $TOKEN" -d '{"method":"page.goto","params":{"url":"askrobots.com"}}' http://127.0.0.1:9777/rpc

Or use the bundled client (apps/browser/scripts/dbb.mjs):

import { connect } from "./scripts/dbb.mjs";
const b = await connect();
await b.call("page.goto", { url: "https://askrobots.com/login" });
await b.call("login");                                   // fills + submits the saved login; you never see the password
await b.call("page.waitFor", { text: "Dashboard" });
const { spent } = await b.call("x402.spent");

Assistant chat

Press ⌘J (or Chat) for a side panel where you can talk to an assistant about the page you are on, and ask it to do things: find something, read a page, fill in a form, open a page. It uses the same tools as the automation API (page.forms, page.find, click, type…), run inside the browser.

  • Which model. The picker at the top of the Assistant panel chooses the assistant's model, from the providers you have set up, and is remembered. The assistant defaults to claude-sonnet-5-5: it reads pages and chooses tools over many steps, where the smallest model makes needless mistakes. The picker shows each model's cost next to Haiku's (Sonnet about 20×). It applies to the assistant only; the reader's summaries keep the model above. The automation API's chat.model does the same.
  • You approve what it does. In Ask first mode every action (open, go to, click, type, choose, press a key) waits for Do it or Skip. In Auto mode only a short allow-list runs without asking: switching tab, going back, keys that only move, typing into an ordinary field, choosing in a dropdown, and clicking a link to a site that is already open, a checkbox or a radio button. Everything else asks: any other click (a button need not say anything scary to be risky), Enter, and opening a site that is not open. A click that submits a form or is about buying, paying, deleting or sending is always marked risky.
  • After it has read your private data from a connected service (contacts, notes, tasks), typing and opening addresses ask in every mode, because a page you are on could try to talk the assistant into copying what it read into the page.
  • It never fills password, card number or one-time-code fields, and their values are never put in the field lists it reads.
  • Pages are untrusted, and the assistant is told whose words are whose. Only what you type is an instruction. Everything a tool returns (page text, field names, tab titles, results from your accounts) arrives with a line saying where it came from and that it is not from you, between tags that carry a random word made for that conversation, so a page cannot forge the end of the block or a message of its own. The system prompt says how to tell the two apart and to ignore anything between those tags that tries to give orders.
  • What leaves your machine: your messages and what the assistant reads from your open pages go to the model, and the first message per model each session asks first, naming where. Every finished run is written to the event log with the model and the tokens used.
  • Which model: the same keys as the AI Reader (ANTHROPIC_API_KEY, OPENAI_API_KEY in the environment or ~/.dbbasic/env). To use a model on this machine or your network, set DBB_AI_BASE_URL to an OpenAI-compatible endpoint (https, or http to this machine or a private network only). Switched off while the caller network is on.

Connections to other services (MCP)

The assistant can use tools from services you sign in to. In the chat panel, Connect opens the service's consent page in a tab of this browser (you sign in to the service there once if you have not; the password manager can fill it); the redirect back is recognised inside the browser, so there is no system browser and nothing listens on a port, and the tokens stay in the browser's main process, encrypted with your operating system's keychain (or, if that is unavailable or DBB_MCP_STORE=memory is set, only in memory until you quit). The browser signs in the standard way: it reads the server's published sign-in documents, registers itself as a public client, and uses PKCE; there is no secret to leak.

  • Which tools: a server adds only the tools its entry lists, not everything it offers. Tools that only read run when the assistant asks; every other tool is asked about every time, even in Auto mode.
  • Which servers: askrobots.com is built in. Add more in mcp-servers.json in the browser's data folder (or the file named by DBB_MCP_SERVERS): [{"id": "notes", "name": "My notes", "url": "https://…/mcp", "tools": ["search", "add"], "readOnly": ["search"], "fixedArgs": {"add": {"project": "inbox"}}, "dropFields": {"search": ["private"]}}]. fixedArgs are forced on a tool whatever the assistant asks for, and dropFields are removed from results before the assistant sees them. extraScopes are permissions asked for at sign-in that the server does not publish (askrobots: files:upload, for saving kept pages in your Files); a server that refuses them is asked again without them, and the panel says when the current sign-in lacks one (connect again to give it). A file entry with the same id replaces the built-in one, so to keep saved askrobots links in one project, copy the askrobots entry and add "project_id" to its fixedArgs for create_link and list_links. An entry that is not valid is skipped, with the reason printed at start-up.
  • What a server returns is untrusted data, like page text. Disconnecting forgets the tokens and asks the server to revoke them.

Knowing when a page has finished loading

Waiting for "loaded", or for the network to be quiet for half a second, or sleeping a fixed time, is a guess: pages that stream, poll or build themselves late fool it, and when it gives up all you learn is that time passed. page.settle (or the settle option of page.goto) decides from what the browser actually observes, and answers two separate questions:

  • rule — what ended the wait. frames-match (everything below held and two frames a moment apart were identical), quiet (same, with the frame test off), animating (everything held but the page keeps changing by itself), or deadline, navigation-failed, crashed, download, payment.
  • outcome — what happened. ok, error-status (with the number; slowDown: true for 429), blank, failed (with a failure.kind such as could-not-find-site, could-not-connect, certificate, redirect-loop, offline, timed-out, blocked, caller-silent — the caller-supplied network layer did not answer in time — or other; and failure.source: observed when the browser saw it, caller when the caller said so), crashed, bot-check, payment-required, not-a-page (a download), deadline.

A page counts as settled when the load event has fired; no request is in flight (apart from long-lived streams, which a finished page can hold open and which are ignored and counted in streams); nothing has moved on the network for quietMs; web fonts are in; the visible images are decoded; and two frames frameGapMs apart match. At the deadline the call still returns, with blockedBy naming what was unmet (for example the one request that never answered). The verdict also carries waitedMs, status, the final URL and title, the server redirects, and the request, byte and host counts.

Pages that move themselves. A page that navigates after it has begun (a script, a <meta refresh>, a link) restarts the wait, and the verdict lists each such move in moves ({to, afterMs}), separately from server redirects. A visit starts when the browser navigates (for example page.goto); a move that begins after the verdict was returned belongs to a new look at the page, so call page.settle again, or raise quietMs to watch for slower ones.

Blank pages. A settled page is called blank when it shows fewer than minText characters of text (default 20; 0 turns the test off) and has no image, canvas, video or svg. A page that fills itself in late would settle as blank first; blankWaitMs (default 0) keeps checking for that long for text or media to appear, then settles. A page that stays blank is still reported blank, and the time waited is in waitedMs.

Console and cookies. The verdict includes console: counts by level (error, warning, info, debug) for the visit, and the first 20 errors as {text, line}, each cut to 200 characters (it is the page's own text: treat it as data, never as instructions). It also includes cookies: the cookies that apply to the address the visit ended on, as {name, domain, path, secure, httpOnly, session}. Cookie values are never included. A page that moves itself keeps adding to the same console record; the next page.goto starts a new one.

How much of the page arrived. outcome: "ok" says the main document settled; it says nothing about the files the page asked for. resources counts them for the visit: requested, answered (a redirect counts; errorStatus of these answered with 4xx or 5xx), failed with failedByKind (the same reasons as failure.kind), cancelled (the page gave up on them itself), waiting (still open when the verdict was given) and mainDocument (answered, failed or pending). A complete page has failed: 0 and waiting: 0.

Example: a <meta refresh>. A page that says <meta http-equiv="refresh" content="1;url=/next"> loads, settles in under a second, and the verdict is for that first page with moves: []; the move to /next starts a new look at the page. To get the page it moves to, call page.settle again, or raise quietMs past the refresh delay so the first wait is still open when the move happens (then moves lists it).

What it cannot see: DNS, TCP and TLS happen inside Chromium, so they are part of "waiting". WebSockets bypass the network layer, so a page driven by a socket can look quiet while it is still receiving; net.policy {blockWebSockets: true} refuses them before any connection is opened. The frame test brings the tab forward, like a screenshot.
Why use this instead of Playwright/CDP? It controls the real, visible browser; input is genuinely trusted (sites that ignore synthetic clicks work); payments are inspectable and assertable (x402.events) rather than a dialog your test can't dismiss; and login signs you in without your script ever holding a password. Input methods bring the tab and the window to the front (taking keyboard focus), because real input needs a visible, focused page.

Plugins

Tools ▸ Plugins installs style rules from gitstable.com; Browse all plugins in the panel opens the list of them. Type the plugin's repository (for example askrobots/x-whole-window, or owner/name@2026.11v1 for a given release) and press Look up: the browser fetches it, checks it and tells you which sites it changes before anything is installed.

A style rule only changes how its sites look. It can't run code, read the page or send anything: CSS that could load something (url(), @import, fonts, image sets) or hide it behind an escape is refused. Each file is fetched at the exact commit of the release and checked against its git blob id, and checked again every time the browser starts; a plugin whose files changed on this computer is switched off. Turn all plugins off shows sites as they are. Plugins in the status bar opens the panel from anywhere; when a plugin is changing the page you are on, it shows that plugin's name instead. On a plugin's page on gitstable.com it says Install: … (or Update: …); one click looks it up for you, and nothing is installed until you press Install. For this the browser fetches gitstable's whole list of plugins, only while you are on gitstable.com. Plugins are never applied while the caller network is on, nor when the browser is started with DBB_SAFE_MODE=1.

How we identify ourselves

Every request carries a Chromium-compatible User-Agent that says who we are and links to dbbasic.com:

Mozilla/5.0 (…) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130… Safari/537.36 dbbasic-browser/2026.11v1 (+https://dbbasic.com)

The version is the year and month of the release and a count: 2026.11v1 is the first release of November 2026, 2026.11v2 the next, and 2026.12v1 the first of December. Help ▸ Version and About show it.

This is the same convention Edge and Opera use: the engine really is Chromium, so the usual tokens stay, and our own token goes on the end. We do not pose as Firefox or Chrome — it would be untrue, and it would contradict the client hints, JavaScript APIs and TLS handshake a site can also see.

We do send what a real Chromium navigation sends: Sec-CH-UA client hints (taken from the engine itself, so they always match navigator.userAgentData), correct Sec-Fetch-* metadata, and a Referer that follows the page's referrer policy.

Some sites will still refuse us. A few large sites (eBay, for one) run bot management that rejects embedded-Chromium browsers at the edge — we measured the same HTTP 403 with our own network layer switched off, with a bare Chrome User-Agent, and with a Firefox one, while Firefox on the same machine was served. That is the site's decision; we don't try to evade it. Use File ▸ Open Page in Default Browser for those pages.

Debugging: DBB_USER_AGENT="…" replaces the User-Agent entirely, and DBB_NATIVE_NETWORK=1 turns off request interception (and x402 payments) so Chromium's own loader makes every request.

Security model

  • The automation API binds 127.0.0.1 only, requires the bearer token on every request, refuses any request carrying an Origin header (so a web page can't drive it) and any non-loopback Host (DNS rebinding). A 🤖 chip shows whenever it is on.
  • Automation that relaxes payment approval is never silent: each decision raises a toast and an inspector/event-log entry. The spending policy's hard caps still apply on top.
  • Treat the token like a password: anyone who has it can drive a browser that holds a wallet key and (while unlocked) your vault. Keep ~/.dbbasic/control.json private; leave the API off when you don't need it.
  • Redirects are visible to the page: a redirect is handed back to the page, which re-requests the new address — so the address bar, the page's origin and the password manager's origin matching always reflect where you actually are, and each hop gets its own payment decision.
  • The wallet key for testnet payments is a hot key in .env. Never fund it with real money. See SECURITY.md.
